# 需求文档生命周期

## 适用条件

用户提供自己创建的原始需求 `.md` 并要求开发、继续开发、审批文档或处理验收 Bugs 时，强制使用本流程。该流程优先于快速路径。

原始需求文件是唯一总入口：

- Owner 维护需求正文。
- Agent 维护进度索引。
- 新会话先读总入口，再按索引读取衍生文档并恢复下一步。

## 文件命名

设原始需求文件为 `<目录>/<需求名>.md`：

| 阶段 | 文件 |
|---|---|
| 需求理解 | `<需求名>+需求理解.md` |
| 技术方案 | `<需求名>+spec.md` |
| 开发任务 | `<需求名>+task.md` |
| 验收问题 | `<需求名>+bugs.md`，由 Owner 创建 |

全部文件与原始需求文件同目录。未到对应阶段时不得提前创建。

## 强制状态机

1. 创建需求理解，等待 Owner 审批。
2. 审批通过后创建 Spec，等待 Owner 审批。
3. 审批通过后创建 Task，等待 Owner 审批和开发授权。
4. 按 Task 开发并持续更新进度。
5. 本地验证完成后标记“待 Owner 验收”。
6. Owner 创建 Bugs 后逐条修复，最终仍由 Owner 验收。

任何前置审批未完成时，不得修改生产代码。不得用“用户最终目标是完成开发”“方案很明确”“先写代码再补文档”等理由越级。

## 原始需求文件进度区

Agent 不改写、重排或删除 Owner 正文，只维护文件末尾以下标记区：

```markdown
<!-- AGENT_PROGRESS_START -->
## Agent 进度

- 当前阶段：
- 当前状态：
- 下一步：

### 文档索引

- 需求理解（填写同目录实际文件链接）：`未创建 / 待 Owner 审批 / 已审批 / 需更新`
- Spec（填写同目录实际文件链接）：`未创建 / 待 Owner 审批 / 已审批 / 需更新`
- Task（填写同目录实际文件链接）：`未创建 / 待 Owner 审批 / 开发中 / 待 Owner 验收 / 已完成`
- Bugs（填写同目录实际文件链接）：`Owner 尚未创建 / 修复中 / 待 Owner 复验 / 已关闭`

### 最近进展

- YYYY-MM-DD HH:mm：关键节点
<!-- AGENT_PROGRESS_END -->
```

规则：

- 标记区不存在时自动追加；已存在时只更新区内内容。
- 链接使用相对于原始需求文件目录的文件名。
- 最近进展倒序、精简记录，不复制 Task 详情。
- 创建文档、Owner 审批、Task 状态变化、验证完成、Bug 修复或方案更新后，同一轮更新索引。
- 索引和衍生文档不一致时，以 Owner 最新指令和衍生文档实际状态为准，并立即修正索引。

## 三份前置文档

### 需求理解

至少包含：

- 文档状态和材料来源。
- 背景、目标、范围与非范围。
- 当前链路、目标主流程和接口契约。
- 旧路径、异常降级、竞态边界。
- Android、HarmonyOS 或其他端参考结论及端差异。
- 可验证的验收标准。
- 待 Owner 确认项。

状态必须为“待 Owner 审批”或“已审批”。Owner 审批前不得创建 Spec。

### Spec

至少包含：

- 文档状态及已审批需求理解链接。
- 当前链路和目标链路。
- 数据、状态、生命周期、UI、播放器和交互职责归属。
- 接口、模型、模块和公共能力变化。
- 线程、内存、复用、取消和竞态策略。
- FF、回滚、异常、日志与监控。
- 影响文件、测试策略和验收路径。
- 方案选型、替代方案和待 Owner 确认项。

状态必须为“待 Owner 审批”或“已审批”。Owner 审批前不得创建 Task。

### Task

按可独立验证的能力拆分，每项包含：

- 状态：`待开始 / 进行中 / 已完成 / 阻塞`。
- 目标、边界、依赖和依据。
- 主要代码位置。
- 不能影响的旧行为。
- 完成标准和验证命令。
- 实际改动、验证结果、偏差和剩余项。

Owner 审批前不得开发。开发时先把当前任务标为“进行中”，完成和验证后改为“已完成”。开发结束时文档总状态改为“待 Owner 验收”。

## 实现期同步

Agent 自行判断是否需要更新前三份文档：

- 需求事实或验收变化：更新需求理解、Spec、Task。
- 职责归属或方案变化：更新 Spec、Task；影响需求行为时同时更新需求理解。
- 文件或执行顺序变化但方案不变：更新 Task。
- 实质改变产品行为、范围、协议、公共职责或风险接受度：暂停实现，等待 Owner 重新审批。

## Bugs 闭环

Owner 创建 `+bugs.md` 并列出问题。Agent：

1. 按文档顺序一次处理一个 Bug。
2. 保留 Owner 原文。
3. 每修完一条，在该条下追加：

```text
原因：一句话说明根因。
修复：一句话说明修复方案。
```

4. 同步 Task 和入口索引。
5. Bug 暴露需求或方案遗漏时，主动更新需求理解、Spec、Task；若边界实质变化，先请 Owner 审批。
6. 所有 Bug 修完后标记“待 Owner 复验”，不得自行宣布验收通过。

## 禁止项

- 把本流程写入工程仓库的 `CLAUDE.md`、`AGENTS.md` 或业务代码文档；这是 Agent skill 的职责。
- 未经 Owner 审批越级创建下一阶段文档或修改生产代码。
- 把本地编译通过等同于 Owner 验收通过。
- 改写 Owner 原始需求正文。
- Agent 自行创建 `+bugs.md`。
