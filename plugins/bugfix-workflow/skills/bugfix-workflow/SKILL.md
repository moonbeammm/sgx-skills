# 播放用户反馈排查

## 原则

不靠猜测归因。用用户信息、Fawkes 日志、接口数据和代码链路证明根因。

## 流程

1. 收集用户反馈基础信息：
   - `mid`
   - `buvid`
   - App 版本、平台、设备和发生时间
   - `avid/cid/epid/roomid` 等内容标识
   - 复现步骤和实际表现
2. **REQUIRED SUB-SKILL:** 使用 `fawkes:fawkes-laser` 或 `mcp-free-skills:fawkes-all` 查询日志。
3. 先查询用户是否已反馈日志；没有日志时再通过 `buvid` 发起拉取。
4. 根据日志时间线定位播放链路：
   - 路由和输入参数
   - view/playview 或业务接口
   - Resolver 和播放器初始化
   - 状态写入与后续覆盖
   - UI 或播放器最终表现
5. 对照当前版本代码确认职责归属和触发条件。
6. 输出证据、根因、影响范围和建议修复。

## 输出

- 用户与环境信息。
- 关键日志时间线。
- 代码链路。
- 已排除的可能性。
- 确认根因或仍缺少的证据。
- 修复建议、FF 止损和验证路径。

如果证据不足，明确需要补充什么日志，不把推测写成结论。
